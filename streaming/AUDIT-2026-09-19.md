# Audit alur video Gaul FM — 19 September 2026

Perbaikan server dan panel telah diterapkan ke Azure dengan backup. Panel tetap tanpa password sesuai instruksi pengembangan. Konfigurasi YouTube dipertahankan: pengiriman nonaktif, stream key tersimpan. Tidak ada tayangan publik YouTube yang dimulai dalam pengujian ini.

## Alur dan sumber aktual

vMix mengirim H.264/AAC melalui RTMP ke path `gaulfm`. Video disalin tanpa encoding ulang. Cabang WebRTC mengubah audio menjadi Opus dan menerbitkan `gaulfm_webrtc`; HLS menggunakan `gaulfm` agar audio tetap AAC. Cabang YouTube menyalin H.264/AAC ke RTMPS ketika operator mengaktifkannya.

Sumber pengujian aktual berupa color bars dengan audio senyap: 854×480, 25 fps, H.264 Constrained Baseline, tanpa B-frame, keyframe sekitar 2 detik, AAC 48 kHz stereo. Sampel ini membuktikan pengiriman dan pemutaran, bukan kualitas gerakan kamera, lip-sync percakapan, atau kapasitas bitrate studio.

## Temuan dan perbaikan

| Bagian | Masalah | Perbaikan |
|---|---|---|
| Transcoder | Handler penghentian menunggu subprocess saat lock wait masih terpegang; ditemukan 19 hook lama tersangkut dengan anak zombie | Handler hanya mengirim terminate; tunggu dan batas kill dilakukan di loop utama. Hook tersangkut dibersihkan; satu hook sehat berjalan |
| Timestamp | Jalur input RTSP menghasilkan peringatan DTS mundur pada sampel | Baca RTMP asli langsung, pertahankan video copy dan resampling audio |
| Muxing | `max_interleave_delta=0` berarti waktu tunggu tidak dibatasi | Batas 100 ms dan flush paket, timeout input 10 detik |
| Relay YouTube | Proses hidup dianggap streaming, pergantian key tidak selalu memulai ulang proses, retry tidak terkontrol | Status berdasarkan kemajuan FFmpeg, deteksi macet, restart saat konfigurasi berubah, retry bertahap, penghentian terbatas |
| Config | Penulisan bisa terpotong, kegagalan simpan tidak jelas, nilai boolean bisa keliru | Tulis atomik, validasi tipe, error diteruskan; toggle tanpa key mempertahankan key lama |
| Rahasia | Key dapat muncul pada respons/log | Respons hanya mengembalikan indikator key tersimpan; log disensor; API internal bind loopback |
| Panel | Polling menimpa draft, status server menyesatkan | Pisahkan draft dan nilai tersimpan, lindungi respons lama, tampilkan kegagalan koneksi dan status pengiriman |
| Preview admin | Lifecycle HLS bocor, buffer besar, kegagalan autoplay tidak jelas | Komponen terpisah dengan cleanup, batas buffer, tombol pemutaran/retry dan watchdog |
| HLS browser | Chrome Windows menjawab dukungan native `maybe` tetapi video macet | Dahulukan HLS.js jika MediaSource tersedia; native untuk browser yang memerlukannya |
| Mobile HLS | Fallback memakai path Opus yang kurang kompatibel | Gunakan HLS dari sumber AAC `gaulfm` |
| Mobile WHEP | Offer belum mengandung kandidat terkumpul, track dianggap bukti video, disconnect setelah tersambung tidak pulih | Tunggu ICE terbatas, validasi kemajuan waktu video, fallback dan retry, hapus sesi WHEP terlambat |
| Mobile lifecycle | Pemutar dapat bertahan saat sheet tertutup/background; sumber HTML berubah saat render | Source stabil, unmount sesuai lifecycle, cleanup track/peer/HLS/session |
| Audio | Stop dapat kalah oleh play yang masih menunggu inisialisasi | Antrean operasi perangkat dan pemeriksaan generasi; video menunggu audio dihentikan |

Semantik batas muxing diperiksa terhadap [dokumentasi FFmpeg](https://www.ffmpeg.org/ffmpeg-all.html). Persyaratan kompatibilitas WebRTC dirujuk dari [MediaMTX](https://mediamtx.org/docs/features/webrtc-specific-features).

## Bukti pemeriksaan

- 15 tes Python lulus, termasuk subprocess POSIX untuk regresi deadlock penghentian.
- 10 tes mobile lulus: SDP, timeout tanpa frame, disconnect, respons terlambat, HLS, escaping HTML, dan race operasi audio.
- 6 tes API admin lulus, termasuk penyimpanan tanpa autentikasi, validasi dan penghilangan stream key.
- Typecheck dan lint mobile lulus; pemeriksaan TypeScript/lint admin serta build produksi server lulus.
- `git diff --check` tidak menemukan kesalahan whitespace.
- Relay diuji dengan sink FLV sementara: 282 paket video, 563 paket audio, tidak ada timestamp mundur pada sampel, FFmpeg exit 0. Ini bukan bukti penerimaan YouTube.
- Browser produksi menampilkan video di monitor admin. Fallback HLS berjalan sekitar 245 detik dengan 5.844 frame dan 4 dropped frame pada sampel tersebut.
- Preview lokal setelah dipulihkan: WebRTC, readyState 4, 854×480, 25 fps, 459 frame, 1 dropped frame, packetsLost 0, jitter 35 ms pada snapshot sekitar detik 18. Statistik adalah sampel sesaat, bukan jaminan kondisi jaringan jangka panjang.
- Deployment tanpa password mengembalikan 400 untuk payload invalid tanpa token, mempertahankan file konfigurasi YouTube byte-for-byte, dan UI tidak lagi meminta password operator.

## Mengapa tombol aktif belum tentu membuat YouTube tayang

Pengiriman video dan status siaran publik adalah dua hal berbeda. Tanpa Auto-start, YouTube dapat menerima video untuk preview tetapi tetap menunggu Go live. Pastikan stream key sesuai siaran yang dipilih. Status lokal pengiriman tidak membuktikan bahwa video sudah publik. Lihat [panduan encoder YouTube](https://support.google.com/youtube/answer/2907883?hl=en) dan [pengaturan siaran](https://support.google.com/youtube/answer/9854503?hl=en).

Stream key hanya untuk ingest. Mengatur judul, memilih/membuat siaran, mengikat sumber video, membaca status dan mengontrol transisi live dari panel memerlukan OAuth akun YouTube serta API. Alur yang dapat ditambahkan: hubungkan akun → pilih/buat siaran → isi judul dan privasi → mulai pengiriman → tunggu sumber aktif → mulai siaran dan tampilkan tautannya. OAuth YouTube berbeda dari autentikasi masuk panel. Integrasi ini belum diimplementasikan. Rujukan: [Broadcasts and Streams](https://developers.google.com/youtube/v3/live/guides/implementation/broadcasts-and-streams).
